# Standards and Currentness

Use standards to classify and verify—not to generate checklist findings.

Useful baselines include:

- current OWASP Top 10 for application risk categories
- OWASP ASVS for verifiable application-security requirements
- OWASP Web Security Testing Guide for authorized web testing methods
- relevant CWE entries for weakness classification
- NIST Secure Software Development Framework for lifecycle context

When citing ASVS, include the version with the requirement identifier if the report depends on exact numbering.

Any claim about a current vulnerable/fixed software version, CVE/GHSA impact, framework default, provider feature, cryptographic recommendation, law/regulation, or active exploitation status must be checked against an authoritative current source at review time.

Prefer vendor security advisories, official release notes, GitHub Security Advisories/CVE records, NIST/CISA/OWASP documents, or the affected project's primary documentation. Secondary blogs may provide leads but should not override primary evidence.
